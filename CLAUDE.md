# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Rust port of Peter Shirley's *Ray Tracing in One Weekend* (RTIOW) series, worked through section by section; commits are named after the book section they finish (e.g. "section 9.5 done"). The whole first book (through chapter 14, the final scene) is implemented, and work has moved on to *Ray Tracing: The Next Week*: the BVH (bounding volume hierarchy), solid (checker) textures, Perlin noise including the marble texture (all of chapter 5), lights, instances (translate/rotate) and the Cornell box are done. Motion blur was skipped, so there is no ray time or moving-sphere code; image textures are not done; and the book's quads are replaced by triangles (see below). *Ray Tracing: The Rest of Your Life* (book 3) is fully implemented: stratified pixel sampling, cosine-weighted diffuse scattering, and importance sampling toward lights with mixture PDFs. Code follows the book's C++ structure and naming closely, adapted to Rust — see "Differences from the book" below.

## Commands

- Build: `cargo build --release` (always render with `--release`; debug builds are far slower)
- Render: `cargo run --release` — writes `gradient.ppm` (plain-text P3 PPM) to the current working directory; scanline progress goes to stdout. The final scene at book settings (1200px, 500 samples/pixel) takes on the order of 10+ minutes on 8 cores; for quick checks, temporarily lower `image_width`/`samples_per_pixel` in `main.rs`.
- Lint: `cargo clippy` (`AABB` keeps the book's name with `#[allow(clippy::upper_case_acronyms)]`)
- Format: `cargo fmt`
- Book 3's standalone Monte Carlo demos live in `examples/` (`pi`, `integrate_x_sq`, `sphere_importance`, `sphere_plot`, `cos_cubed`); run with `cargo run --release --example <name>`. They use only `rand`, not the renderer's modules.

There are no tests.

## Architecture

- **Math types come from `nalgebra`, not a hand-written `vec3`.** `src/rtweekend.rs` defines `Vec3 = nalgebra::Vector3<f64>` and `Point3 = nalgebra::Point3<f64>`; `src/color.rs` aliases `Color = Vec3`. Map book `vec3` operations to nalgebra (`unit_vector` → `.normalize()`, `dot(a, b)` → `a.dot(&b)`, `length` → `.norm()`, `length_squared` → `.norm_squared()`, `cross` → `a.cross(&b)`, `.x()` → `.x`, color `*` color → `.component_mul(&c)`). `Point3` and `Vec3` are distinct types: `Point3 - Point3` yields a `Vec3` and `Point3 + Vec3` yields a `Point3`; mixing them up is a common compile error.
- **Scenes:** as in the book, each scene is a function in `main.rs` (`bouncing_spheres`, `checkered_spheres`, `perlin_spheres`, `cornell_box` (book 2), `shapes` (a test scene for triangle shapes and single-axis, arbitrary-axis and chained rotations), and `cornell_box_sampled` (book 3's final scene)), and `main` picks one with a `match` on a hard-coded number; change that number to switch scenes.
- **Rendering pipeline:** each scene builds a `HittableList` world of `Sphere`s and `Triangle`s, wraps it with `BVHNode::from_list(world)`, configures a `Camera` through its public fields, and calls `cam.render(&world, lights)`. `lights` is `Option<&dyn Hittable>`: the objects to aim extra rays at, or `None` for scenes lit by the sky. `Camera::render` calls `initialize()` (derives image height, viewport, u/v/w basis, defocus disk, and `sqrt_spp`: samples per pixel is rounded down to a perfect square), shoots one jittered ray per cell of a `sqrt_spp × sqrt_spp` grid in each pixel (stratified sampling), and `ray_color` recurses up to `max_depth` bounces. At each hit it adds the material's `emitted` light; for `Scatter::SkipPdf` it follows the given ray, and for `Scatter::Pdf` it picks a direction from a 50/50 `MixturePdf` of the material's PDF and a `HittablePdf` toward `lights` (the material's PDF alone when `lights` is `None`), weighting by `scattering_pdf / pdf_value`. A ray that hits nothing returns `Camera::background`, or the sky gradient when that is `None`.
- **Hittables and bounding boxes:** `src/hittable.rs` defines two traits: `Hittable` (`hit`) and `BBox` (`bounding_box() -> AABB`), with `BBox` as a supertrait of `Hittable` so a `dyn Hittable` can report its box. Every hittable implements both, in separate `impl` blocks. Each object computes its `AABB` (`src/aabb.rs`) once at construction and stores it in a `bbox` field; `HittableList::add` grows the list's box as objects are added.
- **BVH:** `src/bvh_node.rs` builds the tree by taking the bounding box of the objects, splitting along its longest axis, sorting on that axis, and recursing on each half; 1 or 2 objects are stored directly. `hit` tests the node's `AABB` first, then only accepts a right-child hit that is closer than the left one.
- **Materials:** `src/material.rs` has the `Material` trait plus `Lambertian`, `Metal` (with fuzz), and `Dielectric` (refraction + Schlick reflectance). `Lambertian` holds an `Arc<dyn Texture>`: `Lambertian::new(color)` wraps a `SolidColorTexture`, `Lambertian::from_texture(tex)` takes any texture. Each `Sphere` holds an `Arc<dyn Material>`, and `HitRecord.mat` carries it back to the camera.
- **Textures:** `src/texture.rs` has the `Texture` trait (`value(u, v, p) -> Color`), `SolidColorTexture`, and `CheckerTexture` (a 3D spatial checker; `new` takes two textures, `from_colors` two colors). `NoiseTexture` wraps a `Perlin` (`src/perlin.rs`: gradient-vector noise, Hermite-smoothed, plus `turb`) and a `NoiseStyle` (`Smooth`, `Turbulence`, or `Marble`), where the book instead edits `value()` for each image; `perlin_spheres` shows all three side by side on a plain ground. `HitRecord` has `u`/`v` fields, but `Sphere::hit` sets them to 0 until sphere UV mapping (section 4.5) is done.
- **Triangles:** `src/triangle.rs` has `Triangle` (Möller–Trumbore intersection; barycentric coordinates become `u`/`v`; front face is where the vertices appear counter-clockwise), plus `add_quad(list, q, u, v, mat)` (a parallelogram as two triangles, same parameters as the book's `quad`) `make_box(a, b, mat)` (12 triangles), `make_pyramid(base_center, base, height, mat)` (square pyramid, 6 triangles) and `make_prism(center, width, height, depth, mat)` (triangular prism along z, 8 triangles). All of these return a `HittableList` with normals pointing outward.
- **Instances:** `src/instance.rs` has `Translate` and `Rotate`. Both wrap an `Arc<dyn Hittable>`, move the incoming ray into the object's space, and move the hit back out. `Rotate::new(object, axis, degrees)` rotates about any axis through the origin using nalgebra's `Rotation3`; its bounding box is the box around the 8 rotated corners. Wrap a `make_box` list directly: `HittableList` is itself a `Hittable`.
- **Lights:** `Material::emitted(r_in, rec)` defaults to black; `DiffuseLight` overrides it, emits only from its front face (so an `add_quad` light shines along `u × v`), and never scatters.
- **Importance sampling (book 3):** `src/pdf.rs` has the `Pdf` trait (`value`, `generate`) with `SpherePdf`, `CosinePdf`, `HittablePdf` and `MixturePdf`; `src/onb.rs` has the orthonormal basis `Onb`. `Hittable` has `pdf_value(origin, direction)` and `random(origin)` with do-nothing defaults; `Triangle`, `Sphere`, `HittableList` (an equal mixture of its members), `Translate` and `Rotate` implement them. A scene's lights list holds separate copies of the light geometry (two triangles for a quad light); their material is only a placeholder.
- New modules are registered via `mod` in `main.rs`.

## Differences from the book

- **Multithreaded rendering with `rayon`** (not in the book): `Camera::render` computes scanlines in parallel with `into_par_iter()`, collects them, then writes them in order. Because the world is shared across threads, `Hittable`, `Material` and `Texture` require `Send + Sync`, and materials are shared with `Arc` (where the book uses `shared_ptr`). Any new hittable, material or texture must be thread-safe.
- **Random numbers come from the `rand` crate** (`rand::random::<f64>()` inside `random_double`) instead of C++ `rand()`; it is thread-local, so it's safe to call from rayon threads.
- **Output goes to `gradient.ppm`**, not stdout as in the book.
- **BVH ownership:** `BVHNode` children are `Arc<dyn Hittable>` (the book's `shared_ptr`) so a single-object node can point `left` and `right` at the same object. `HittableList` stores `Box`es, which `BVHNode::from_list` consumes and converts with `Arc::from`. `BVHNode::new` panics on an empty object list. `AABB::from_points` calls `pad_to_minimums`, so boxes of flat (axis-aligned) triangles are never zero-thickness.
- **Separate `BBox` trait:** the book puts `bounding_box()` on `hittable` itself; here it lives in its own `BBox` trait, required by `Hittable`. Rust can't write `dyn Hittable + BBox`, so the supertrait is what lets a `dyn Hittable` expose its box.
- **`Option` instead of out-parameters:** `Hittable::hit` returns `Option<HitRecord>` (not `bool` + `hit_record&`), and `Material::scatter` returns `Option<ScatterRecord>`. The book's `scatter_record` with `pdf_ptr`/`skip_pdf`/`skip_pdf_ray` is a `ScatterRecord { attenuation, scatter }` where `scatter` is the enum `Scatter::Pdf(Box<dyn Pdf>)` or `Scatter::SkipPdf(Ray)`.
- **PDFs borrow instead of `shared_ptr`:** `HittablePdf` and `MixturePdf` hold references with a lifetime and are built on the stack inside `ray_color`; only the material's PDF is boxed. PDFs are per-thread, so `Pdf` does not need `Send + Sync`.
- **`Material::emitted(r_in, rec)`** takes the hit record instead of the book's separate `u, v, p` (which are in the record).
- **Light sampling guards (not in the book):** `ray_color` skips a sample whose mixture `pdf_value` is 0 instead of dividing by it, and `Sphere`'s cone sampling clamps `1 - r²/d²` at 0 so a point on the sphere can't produce NaN. `write_color` also zeroes NaN components, as in the book. `render` takes `lights` as an `Option` so scenes without lights skip light sampling instead of dividing by an empty list.
- **`Translate` and `Rotate` forward `pdf_value`/`random`** to the wrapped object (the book's instances don't), so transformed objects can be sampled as lights.
- **`vec3.h` helpers are free functions in `rtweekend.rs`** (`random_vec3`, `random_vec3_min_max`, `random_unit_vector`, `random_on_hemisphere`, `random_in_unit_disk`, `near_zero`, `reflect`, `random_int`, `refract`, `degrees_to_radians`), since methods can't be added to the nalgebra type aliases. The book's `infinity` and `pi` constants are not defined; use `f64::INFINITY` and `std::f64::consts::PI`.
- **Triangles instead of quads:** chapter 6's `quad` is not implemented; flat shapes are built from `Triangle`s via `add_quad`/`make_box`. The book's `box` function is `make_box` (`box` is a Rust keyword).
- **Isotropic material and `ConstantMedium` (smoke) are not implemented**, so `SpherePdf` is unused and kept with `#[allow(dead_code)]`.
- **`Rotate` takes any axis** instead of the book's `rotate_y`; use `Vec3::y()` for the book's behavior.
- **`Camera::background` is an `Option<Color>`**: the book sets a background color in every scene; here `None` (the default) keeps the sky gradient for the earlier scenes.
- **Overloaded constructors get distinct names**, since Rust has no overloading: `CheckerTexture::new`/`from_colors`, `Lambertian::new`/`from_texture`, `DiffuseLight::new`/`from_texture`.
- **`Camera::new()`** sets the book's defaults; settings are public fields assigned in `main.rs`, and derived values are private fields filled in by `initialize()`.
- Unused parts of the book's API (`HittableList::clear`, `Interval::UNIVERSE`, `AABB::UNIVERSE`, `random_on_hemisphere`, `near_zero`, `SpherePdf`) are kept with a narrow `#[allow(dead_code)]` so the build stays warning-free.

Edition is 2024.
